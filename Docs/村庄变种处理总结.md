# 村庄变种处理总结

## 问题

用户指出：村庄有许多变种（平原、沙漠、热带草原、针叶林、雪原），当前实现是否正确处理？

---

## 分析结果

### 策略 1：种子推演（有种子）✅ 已正确处理

**机制**：
- 输入 `struct_keys=("village",)` → 匹配所有村庄变种
- 遍历 5 种村庄群系（`_check_village`）
- 对每个变种调用 `_village_variant()` 计算旋转和尺寸
- 群系校验通过后返回**统一类型**：`"struct": "village"`

**变种覆盖**：
| 变种 | 群系 ID | 尺寸配置数 |
|------|---------|-----------|
| 平原村庄 | PLAINS (1) | 8 种 |
| 沙漠村庄 | DESERT (2) | 6 种 |
| 热带草原村庄 | SAVANNA (35) | 8 种 |
| 针叶林村庄 | TAIGA (5) | 4 种 |
| 雪原村庄 | SNOWY_PLAINS (12) | 6 种 |

**优点**：
- 自动覆盖所有变种，用户只需输入 `village`
- 返回统一的 `"village"` 类型
- 精确定位（基于 cubiomes 算法）

---

### 策略 2：解析 NBT（无种子）⚠️ 已修复前缀匹配问题

**问题**：
- 用户输入：`village`
- NBT 实际存储：`minecraft:village`（带命名空间）
- 原代码：`if st_type != struct_type` → 匹配失败

**修复**：
```python
# 宽松匹配：忽略 minecraft: 前缀
normalized_input = struct_type.lower()
normalized_nbt = st_type.lower().replace("minecraft:", "")

if normalized_input != normalized_nbt:
    continue
```

**现在支持**：
- ✅ 用户输入 `village` 匹配 `minecraft:village`
- ✅ 用户输入 `village` 匹配 `village`
- ✅ 大小写不敏感

**变种信息**：
- Java 版 1.18+ chunk NBT 中，所有村庄变种统一存储为 `village`
- 变种信息可能存储在 `Children[].Name` 字段（如 `"minecraft:village/plains"`）
- 当前实现：不区分变种，统一返回 `"village"` 类型
- 可选扩展：支持 `village_plains` 等变种查询（需确认 NBT 存储格式）
